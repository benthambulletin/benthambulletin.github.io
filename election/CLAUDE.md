# The Ballot — /election/ refresh rules

`/election/` is a public tracker Garret shares by link: https://benthambulletin.github.io/election/. It is a standalone page: no mention of The Bentham Bulletin, the paper, or any link back to the home page anywhere on it (Garret, Oct 14). It only happens to live in this repo. One job: every morning through Nov 4, 2026, bring `election/data.json` up to date and rebuild.

## Files
- `election/data.json` — every number on the page. Each row keeps its `url` (source). Keys: `as_of`, `updated_at`, `bottom_line` (six items, `order`/`headline`/`detail`), `what_changed` (list of plain sentences; empty if nothing moved), `generic_ballot`, `approval`, `senate`, `control`, `ny_governor`, `ny_house`, `statewide` (the four races on every NY ballot), `your_ballot` (five towns — North Tonawanda, Orchard Park, Scottsville/Wheatland, Dunkirk, Fredonia/Pomfret — each a list of `office`/`race`/`url` items: US House, State Senate, Assembly, county seats, local offices and propositions, early-voting site), `outlook` ("What could still change this" — the editor's read on what could move the race; rewrite it only when the picture actually changes, e.g. a ceasefire, a gas spike, early-vote numbers; it is labeled judgment, keep it short and even-handed), `how_to_read` (the calm box under the tiles — stable text, reword only if a line becomes untrue), `election_night` (count-timing expectations; verify Maine RCV status and Alaska dates once more the week of Nov 1), `glossary` (plain-English definitions shown under the tiles — keep them current when the Senate math or the tile sources change; Garret, Oct 14: "if I didn't know, no one else will"), `key_dates`, `history` (one row per day: date, generic_ballot, trump_net, dem_senate_odds, hochul_margin).
- `election/build.py` — renders `index.html` from data.json. Run `python3 election/build.py` from the repo root. Never type a number into build.py or index.html.

## Each run
1. Research, in this order, and read the date inside each page, not the "updated" badge: Silver Bulletin generic-ballot page; RealClearPolling generic ballot and Senate toss-up map (the race pages for ME, OH, TX, IA, KS and any new toss-up); Cook Senate ratings (note rating changes); RealClearPolling's Trump approval page (the RCP average row plus each listed poll — Wikipedia's aggregator table lags by weeks, do not use it) and Silver Bulletin's net approval; Polymarket/Kalshi Senate odds (any reporting site is fine, dated); Emerson, Marist, Siena for NY governor; Emerson/Siena for NY-17; any NY-01 or NY-04 poll; the five-town ballot box only when something changes (a candidate drops, a proposition is added or struck, early-voting details change): theballotbrief.com ZIP pages (14120, 14127, 14546, 14048, 14063) and the Erie, Niagara, Monroe and Chautauqua boards of elections; WKBW, WXXI, Chautauqua Today, Dunkirk Observer for local items. Two items are marked unconfirmed in the data (Orchard Park SD-60 opponent; Orchard Park Town Justice candidates) — resolve them when a county sample ballot appears and drop the word unconfirmed.
2. Update data.json. Replace a row's poll only with a newer one; keep the row's `note` current (prior poll, rating moves). Rewrite `bottom_line` so it reads true today — six items, one line each, plain English, no cheerleading, no endorsements. Fill `what_changed` with what actually moved since yesterday (rating changes, a new poll that shifted a lead, a candidate event); leave it empty if nothing did. **Frame it around the path to a Democratic Senate majority (Garret's ask, Oct 14):** lead with any movement in the seats Democrats need to flip — Maine, Ohio, Texas, Iowa, Kansas, Alaska — and in the holds that could undo it (Michigan, Georgia, North Carolina), and say in the same sentence what the change does to the net-plus-four math ("Iowa tightened toward Hinson; the four pickups now run through Maine, Ohio, Texas and Kansas"). Other movement (House, governor, approval) follows. The wording stays factual and the rest of the page even-handed: no cheerleading, no endorsements. Append today's `history` row. Set `as_of` to today and `updated_at` to now (Eastern, ISO).
3. **Independent fact-check before building (non-negotiable).** Spawn a fresh sub-agent (Agent tool, general-purpose) that has not seen your research. Give it the path to election/data.json and tell it to open every row's url, read the number on the page and the date inside the page, and return a ranked list of mismatches with replacement values plus a VERDICT (CLEAN / MINOR / SERIOUS). Fix every item it lists. Do not publish on SERIOUS until it is fixed and re-checked. Keep the verdict and what was fixed in one line in the commit message.
4. `python3 election/build.py`, then render at 390px with Playwright and Read the screenshot; check no "None", no "—" where a number should be, dates correct.
5. `git pull --rebase`, commit `Ballot — Month D` with only `election/` changed, push. Confirm the page serves (`curl -s https://benthambulletin.github.io/election/ | grep -c "Updated <today>"`).
6. Say nothing to Garret unless the run failed or something big moved (a rating change in a Senate toss-up, a NY poll outside the prior range) — then one line with SendUserMessage.

## Rules
- **Write for someone who doesn't follow politics (Garret, Oct 18: "if I'm not understanding, nobody else will").** Every `what_changed` item is ONE plain sentence first — who leads whom, by about how much, which way it moved — with a name and a (D)/(R) on every person named. No pollster names, dates, sample sizes or "RCP average" in that first sentence; put them in a second sentence if they matter, and the page folds everything after the first sentence behind "More". Say "about 3 points", not "+3.3". Never write a bullet a reader has to decode. A `margin` is only set when a nonpartisan poll or an average from the last ~3 weeks supports it; a lone partisan or stale poll goes in `note` and `margin` stays null, so the page says "No public poll yet" rather than claiming a lead. The race rows are rendered as plain sentences by build.py from the data; the `note` field is the only place for pollster detail and it is hidden behind "Show the polls".
- **Sabato's Crystal Ball:** centerforpolitics.org refuses automated fetches. Read its rating changes through a dated secondary (Newsweek, The Hill, Political Wire, 270toWin's change log) and cite that; don't mark the row "not refreshed" if a secondary from the same week confirms it.
- **Oct 15 (Garret): readers are nervous.** The page's job is to keep them steady and informed, not to soothe or alarm. The steadiness line (7-day deltas from `history`) is computed by build.py; never edit it by hand. When early voting opens Oct 24, add a short "What you can do" item (check registration, early-vote sites, bring a friend) to the banner — non-partisan.
- **Oct 14 fact-check lesson:** a search snippet is not a source. The first build cited an approval table to Wikipedia that the page did not actually show, called three Senate races "no poll" when RCP listed polls days old, and cited a House rating to a site that said the opposite. Before writing a row, open the url and read the number on the page; before writing "no poll", check RCP's latest-polls list for that state.
- Never print a number without a dated source row in data.json. If a source can't be read today, keep yesterday's row and say so in `what_changed` ("RCP Senate average not refreshed today").
- **Prefer averages over single polls.** For every Senate row use the RealClearPolling race-page average (and Silver Bulletin's where readable) as the headline number; a single poll goes in `note`, not in `dem_pct`/`rep_pct`, unless no average exists. When the only recent poll is from a partisan or low-rated firm (InsiderAdvantage, Trafalgar, Rasmussen, co/efficient, McLaughlin, any campaign internal, any pollster marked (R) or (D)), say so in the row's `note` in plain words ("Republican-leaning pollster") so readers can weigh it. Never let a single such poll move a bottom-line sentence on its own.
- Margins are Democrat minus Republican. `cook_rating` uses Cook's words.
- Nov 4 run: results special — replace polls with results where called (AP), keep the layout. After Nov 4 the task should be deleted.
- The Your-ballot box is reference, not news: keep it one `office`/`race` line per item, every item sourced, and never pad a town that has nothing.
- **Party tags (Garret, Oct 18):** every candidate name on the page carries a colored (D)/(R). build.py does it for the Senate, governor and House rows; in free-text fields (`your_ballot[*].items[*].race`, `statewide`) write the tag yourself after every name — "Smith (R, inc.) vs Jones (D)" — and build.py colors it. Never leave a name without one.
- Don't touch anything outside `election/`.
